# Test results

Verified on 16 November 2026.

## Build and integration checks

- Four Spring Boot services compile and package for Java 17.
- The React production build succeeds. Vite reports non-fatal React Router module-directive warnings.
- The npm audit reported zero known vulnerabilities at the time of this check. This is not a complete security audit.
- MySQL 8.4.13 runs with the supplied schema and seed scripts.
- The HTTP suites pass against MySQL. The isolated H2 suite is also available for CI.

### API coverage

The smoke suite tests signup/login, signed bearer tokens, role and farmer ownership checks, animal registration, vet profile/listing creation, booking acceptance, antibiotic treatment, pharmacy deduction, withdrawal blocks, safe milk accounting, vaccination, ratings and all six JDBC reports.

Withdrawal checks include the inclusive end date, sales after expiry, permanent exclusion of historical withdrawal milk and overselling rejection. Failure/retry checks confirm that insufficient stock leaves a conservative block and that retries do not deduct twice.

The negative suite additionally checks malformed values, unknown records, duplicate registration/tags/ratings, already-decided bookings, expired medicine and internal-only APIs. Concurrent requests confirm that five stock units permit exactly five of ten deductions, and three available safe litres permit exactly three of five one-litre sales.

## Browser checks

Automated Chromium checks use the live React UI and the local MySQL-backed services. Desktop viewport: 1440 × 1000. Mobile viewport: 390 × 844.

Passed:
- Login image loading, password visibility and incorrect-password feedback.
- Farmer, Vet and Admin login/logout.
- Every role's routed pages, without displayed API errors.
- All six report selections.
- Farmer registration and animal create/edit/delete, including cancelling deletion.
- Inventory creation/editing and the low-stock status change.
- Search navigation, refreshed sessions and protected routes.
- Readable feedback when the backend is unreachable.
- Expired-session logout and removal of stored credentials.
- Mobile login/menu navigation, with no horizontal page overflow.
- No uncaught browser runtime errors.

Screenshots generated by these checks are in [screenshots](screenshots/). They show actual application screens with synthetic demo data.

## Reproduce

With the complete ERP running locally:

```bash
python3 scripts/smoke-test.py
python3 scripts/negative-check.py
cd frontend
npm ci
npx playwright install chromium
npm run test:ui
```

To use an existing browser binary, set CHROMIUM_EXECUTABLE. UI_URL optionally points browser checks to another running instance.

For the isolated backend suite after building:

```bash
bash scripts/test-h2.sh
```

The GitHub Actions workflow builds the project and runs the H2 integration/negative suites. Browser tests run separately against a running application.

## Scope

These checks cover implemented flows and selected failure/concurrency cases. They do not prove that every possible input works. No production load test, penetration test, clinical validation or automatic Java unit-test suite is claimed.

The temporary HTTPS demo was separately verified for login and the main HTTP workflow. Its availability depends on the laptop, network and tunnel session; it is not permanent hosting.
